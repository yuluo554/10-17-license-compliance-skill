## 二、SPDX 快照抓取与冻结（M1）

### 2.1 抓取

```bash
py -3.12 -X utf8 tools/fetch_spdx.py --out references/spdx
```

- 只抓 `licenses.json`、`exceptions.json`，以及规则包实际引用到的许可证全文（不整包下载）。
- 记录：URL、HTTP 状态、字节数、`licenseListVersion`、抓取日期（UTC 日期，不带时刻）。
- 失败重试 ≤3 次，带超时；仍失败 → 中止并**不写半份文件**。
- **抓取是人工步骤，不是运行时行为**；引擎运行期零网络（AST 守门）。

### 2.2 冻结

- 快照文件进 `references/spdx/`，`.gitattributes` 标 `-text`（防止 EOL 改写字节）。
- manifest 登记：`licenseListVersion`、`captured_on`、每个文件的 sha256。
- 重新抓取 = 新版本：更新 manifest 与快照，重跑 `tools/gen_ruleset.py --check` 与全部基准；**旧值不保留在代码里**。

### 2.3 落盘确定性

- JSON 写出统一 `ensure_ascii=False` + `indent=2` + `sort_keys=True`（快照是外部数据，排序只为稳定 diff）+ LF + 结尾换行。
- 生成器两次运行逐字节一致；`--check` 子命令重生成到临时目录并逐字节比对。

## 三、规则包生成（M1–M4）

### 3.1 生成器

`tools/gen_ruleset.py`：

- 输入：`references/spdx/licenses.json`、`references/spdx/exceptions.json`、`references/curated/*.json`（人工核对表）。
- 输出：`references/ruleset/*.json` + `manifest.json`。
- `--check`：重生成到临时目录，逐字节比对；不一致列出文件名与首个差异位置，exit 1。

### 3.2 curated 人工表（唯一手写数据）

`references/curated/` 下每张表是「人工核对过的判定数据」，**不是代码**：

| 文件 | 内容 | 每条必带 |
| --- | --- | --- |
| `tiers.json` | `license_id` → 档位 + 义务项 | `anchor`（许可证文本节号/段落）+ `checked_on` + `verified` |
| `trove-map.json` | trove classifier → SPDX ID | `source_url` + `checked_on` |
| `scenario-triggers.json` | 场景触发表 | `anchor` + `checked_on` + `verified` |
| `conflict-pairs.json` | 冲突对 | `basis` + `anchor` + `checked_on` + `verified` |
| `action-rules.json` | 处置决策表 | `anchor` + `checked_on` + `verified` |

纪律：

- **`verified=false` 的条目不进引擎**（loader 硬门），并出现在 `disabled_rules` 清单里。
- `checked_on` 是人工核对日期，不是生成日期。
- 没有锚点的条目**不得写进 curated 表**；宁缺勿造。
- curated 表的手改必须同时重跑生成器与基准；`--check` 会拦住忘记重生成的情况。

### 3.3 覆盖口径

manifest 登记：

```json
{
  "licenseListVersion": "3.29.0",
  "ruleset_version": "r0.1.0",
  "coverage": {
    "tiers_total_ids": 0,
    "tiers_sampled_ids": 0,
    "note": "首期只覆盖清单实际出现的 SPDX ID；抽样覆盖，非全量穷举"
  }
}
```

- **总数与采样数双登记**；只写采样数 = 假覆盖。
- 未覆盖 ID 在画像里输出 `tier: null` + 待确认，不猜。

## 四、合成依赖清单（M1）

### 4.1 形态覆盖

每个用例目录 `data/synthetic/<case-id>/` 含一个或多个清单文件 + `README.md`（说明覆盖点）：

| 用例 | 覆盖 |
| --- | --- |
| `npm-basic` | `package.json`：字符串 license、对象 license、licenses 数组 |
| `npm-lock-v2` / `npm-lock-v3` | lock 的 packages 映射、根包跳过 |
| `pip-requirements` | `==` 版本、extras、注释、`-r` 行 |
| `pyproject-pep621` | `[project]` + classifiers（trove 链） |
| `pyproject-poetry` | `[tool.poetry.dependencies]` |
| `go-mod` | require 块 + 单行 |
| `maven-pom` | `<licenses>` + 多模块依赖 |
| `expr-complex` | `A OR B`、`A AND B`、`GPL-2.0-only WITH Classpath-exception-2.0` |
| `unknown-and-missing` | 缺失 license、族名 `GPL`、未知例外 |
| `known-traps` | pandas / psycopg2 / PyMySQL / PyQt5 |

包名规则：普通用例一律 `example-pkg-<letter>`；**只有 `known-traps` 用真实包名**，且不进示例报告。

### 4.2 确定性生成

- RNG：自研 `splitmix64`（stdlib `random` 不承诺跨版本序列一致）。
- 禁时钟、禁 `set` 迭代序、禁文件系统枚举顺序；所有列表显式排序。
- 生成后整目录入仓，禁手改；改生成器 → 重生成整目录 + 提交 + `--check` 守门。

### 4.3 坑位用例的期望值

pandas / psycopg2 / PyMySQL / PyQt5 四条：

- 清单字段内容**照实录入**（pandas 的 license 字段为超长全文，约 61K 字符）；
- 期望 `spdx_id` / `confidence` 由**人工核对后写入**，带 `checked_on`；
- 不得用解析器自身输出回填真值；
- pandas 用例必须断言：解析器输出**不是**通过全文关键词匹配得到的（阴性对照：把 license 全文里的 "MIT" 字样保留但首行改为其他，期望仍不命中）。

## 五、真值库（M1 起）

### 5.1 结构

`data/truth/truth.json`（生成物）：

```json
{
  "format": "licaudit-truth",
  "format_version": 1,
  "cases": [
    {
      "case_id": "npm-basic",
      "inputs": {"files": ["package.json"]},
      "expect": {
        "dependencies": [
          {"package": "example-pkg-a", "version": "1.0.0", "spdx_id": "MIT", "confidence": "license_expression"}
        ],
        "pending_confirmation": 0
      }
    }
  ]
}
```

硬纪律：

- **只存输入与期望**；出现 `observed_*` 字段即测试红。
- 期望值由生成器里的**独立朴素 oracle** 算出（不调用生产解析器）；生成器写盘前断言「oracle 重算 == 声明期望」。
- 真值库冻结后 `tools/gen_truth.py --check` 位级一致。
- **用户敲的 `licaudit verify-data`** 必须真读这份冻结件（不是测试里读、CLI 里重生成）。

### 5.2 判定真值

M2–M5 真值分别落：

| 文件 | 内容 | 里程碑 |
| --- | --- | --- |
| `data/truth/profile.json` | 每个采样 SPDX ID 的档位/义务集合 | M2 |
| `data/truth/scenario.json` | 八场景 × 链接方式 → 触发结果 | M3 |
| `data/truth/conflicts.json` | 冲突对与表达式求值 | M4 |
| `data/truth/actions.json` | 每级处置至少一个植入真值 | M5 |

同样只存输入与期望；判定真值的期望由 curated 规则表直接推导（规则表是唯一真相，真值是它的投影），**不是**由引擎输出回填。

## 七、数据纪律汇总

| 编号 | 纪律 |
| --- | --- |
| D-1 | 无出处不得以确定语气落库；查不到 → `待核对` 并继续推进 |
| D-2 | 冻结产物禁手改；改生成器后整目录重生成 |
| D-3 | `--check` 必须两层：冻结产物形态 + 重生成逐字节一致 |
| D-4 | 真值只存输入与期望，观测由运行时实算 |
| D-5 | 台账/生成物登记「输入的函数」，不登记「本环境现状」 |
| D-6 | 快照用 `-text` 防 EOL 改写 |
| D-7 | 计数口径（条目数 / 记录数）在使用处标注单位 |
| D-8 | 抓取日期与数据版本成对出现 |
| D-9 | 合成数据白名单：`example-pkg-*`；真实包名仅限坑位用例 |
| D-10 | 不把「目录里实际有几个文件」这类环境依赖事实写进 manifest |
