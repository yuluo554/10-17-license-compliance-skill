## 四、风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| SPDX 3.29 之后清单变更 | 快照过时 | manifest 记版本；重新抓取是人工步骤，变更走新版本 + 全量重跑 |
| curated 规则覆盖不足 | 大量 `tier: null` 待确认 | 首期只承诺清单实际出现的 ID；双计数登记，明确「抽样覆盖」 |
| 冲突对判定争议 | 结论被质疑 | 每条带 `basis` + 锚点 + 核对日期；OSADL 只作交叉验证；固定免责声明 |
| 八场景与真实交付形态不完全对应 | 用户选错场景 | 场景选择必须落盘 `raw_answer`；矛盾回答 → 待确认，不猜 |
| 3.8 无 `tomllib` | pyproject 解析受限 | 受限子集 + 显式降级；M1 实测后决定是否引入依赖 |
| 单平台开发 | 跨平台编码/路径差异 | CI 四矩阵；本机双解释器 + cp1252 流测试 |
| 规则包与 wheel 安装面不一致 | wheel 用户不可用 | D12 明示发布形态；README 写 `--rules-dir`；不承诺 wheel |

## 五、诚实口径

- 本轮（M0）**没有远端、没有跑过 CI**。所有 CI 相关表述一律写「本地等价校验，未接远端，CI 待首推验证」。
- M0 的 DoD 中「CI 配置就位」只证明文件存在，不证明跑通。
- M1 起每个里程碑收尾在 HANDOFF 中记录：跑了什么命令、退出码、证据文件路径；未跑的项写 ⬜ 并说明原因。
- 发布留档（`plan/RELEASE-M6.md`）只在事实发生后填写，禁止预填。
