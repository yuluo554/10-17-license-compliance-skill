# plan/02 架构与技术选型

> 对应 sprint 阶段 0「架构与技术选型」。本文只定结构、边界与契约；模块算法细节见 `plan/03-模块详设.md`，数据形态见 `plan/04-数据计划.md`。
> 版本：v1（2026-10-17，M0 定稿）。

## 一、交付形态与运行方式

**唯一形态：Agent Skill**。仓库根即 Skill 根：

```
SKILL.md                 # agent 入口：触发条件、工作流、契约块、退出码、限制
scripts/                 # 交付态薄启动器（编码守卫 + 转交包内 main）
src/licaudit/            # 确定性引擎（纯标准库）
references/              # 规则包 + SPDX 快照（数据，不是代码）
data/                    # 数据台账、合成清单、真值（M1 起冻结）
tests/                   # pytest
plan/                    # 计划与留档
MANIFEST.in              # sdist 清单（M6：让源码包自带 references/ 规则包）
```

三种调用方式，**语义完全等价**：

| 方式 | 命令 | 用途 |
| --- | --- | --- |
| 安装后控制台脚本 | `licaudit <subcommand>` | 本机与 CI 的主通路 |
| 模块方式 | `python -m licaudit <subcommand>` | 未安装时可用；包内必须有 `__main__.py` |
| 仓库内启动器 | `python scripts/launcher_licaudit.py <subcommand>` | Skill 场景（agent 直接读仓库）；负责编码守卫 |

三者都汇入 `licaudit.cli.main(argv)`，**只有一份参数解析与退出码实现**。启动器不承担任何业务判断。

### 1.1 运行时边界

- **Python ≥ 3.8**（本机 3.8.8 / 3.12 双通道；CI 矩阵 windows/ubuntu × 3.8/3.12）。
- **运行时零第三方依赖**；`dev` extra 只有 `pytest`。
- **零网络**：引擎源码不得 import `socket` / `urllib` / `http` / `requests`；由 AST 守门测试锁定。SPDX 快照随包冻结，刷新是独立的人工生成步骤（M1）。
- **零 LLM**：全部结论由确定性规则产生；决策记录 D11。不设「LLM 兜底」分支，也不留 API Key 配置面。
- **纯本地**：只读用户给出的清单文件，只写 `--out-dir`；不写用户主目录，不读 `~`。

### 1.2 规则包定位（安装面纪律）

规则包在仓库内 `references/`，**不打进 wheel**。解析顺序固定：

1. `--rules-dir <path>`（显式，最高优先）
2. 环境变量 `LICAUDIT_RULES_DIR`
3. 仓库根推导：本文件所在包向上两级（`src/licaudit/../../references`）
4. 当前工作目录下的 `references/`

四条都取不到 → `RulesetError` → **exit 3**。不做「找不到就用内置默认值」的回落（那等于第二份规则）。

**发布形态口径**：首期发布物是**源码包 / git clone + editable 安装**，README 明示 `--rules-dir` 用法。**不承诺 wheel 安装后规则包可用**；若将来要支持 wheel，必须把规则包收进包内并用 `importlib.resources` 读取，同时改本文件与 README，届时另立决策。

> M6 补充（D37）：上面的「不打进 wheel」只约束 wheel。**sdist 走仓库根 `MANIFEST.in` 的显式白名单**，
> 把 `references/`（规则包 + SPDX 快照）、`data/`、`examples/`、`plan/`、`tools/`、`tests/`、`scripts/`
> 一起打进源码包；否则解包后 `licaudit status` 会因找不到规则包而 exit 3——「源码包」这一形态就不自足。
> 本节上面的**定位顺序不变**（K24）：sdist 只是让仓库快照完整，不新增任何回退来源。

## 二、分层结构

```
                 ┌──────────────────────────────┐
  SKILL.md  ───▶ │  cli.py（唯一入口/退出码）    │
                 └──────────────┬───────────────┘
                                │
                 ┌──────────────▼───────────────┐
                 │  pipeline.py（编排，零判定）  │
                 └──┬────────┬────────┬─────────┘
                    │        │        │
        ┌───────────▼──┐ ┌───▼─────┐ ┌▼─────────────┐
        │ inventory/   │ │ assess/  │ │ report/      │
        │ M1 解析归一  │ │ M2 画像  │ │ M5 渲染      │
        └───────┬──────┘ └───┬─────┘ └──────┬───────┘
                │            │              │
        ┌───────▼────────────▼──────────────▼───────┐
        │ ruleset/（唯一规则来源：tiers / obligations │
        │ / scenario-triggers / conflict-pairs /     │
        │ trove-map / spdx 快照）                     │
        └────────────────────────────────────────────┘
```

硬边界：

| 层 | 允许做 | 禁止做 |
| --- | --- | --- |
| `cli.py` | 参数解析、异常 → 退出码、调 pipeline | 判定逻辑、许可证 ID 判断表 |
| `pipeline.py` | 串步骤、合并退出码、落中间产物 | 重新判定、复制规则表 |
| `inventory/` | 解析清单、SPDX 归一化 | 读场景、读 outbound、判冲突 |
| `assess/` | 画像/场景/冲突（只消费规则包） | 生成报告文案、新增义务项 |
| `report/` | 渲染既有结论（MD/CSV） | import 判定模块、算术、内联许可证判定 |
| `ruleset/` | 加载/校验规则包 | 内置第二份规则默认值 |

`report/` 的「零判定」由 AST 守门（M5 已落地，见 `tests/test_report.py`）：禁止 import `inventory`/`assess` 子模块、禁止 `BinOp`（仅豁免两侧都是字符串常量或 f-string 的拼接）、禁止内联许可证 ID / 档位名 / 处置级别名字面量，并禁止读盘与读时钟。

## 三、产物与契约

产物全部落 `--out-dir`（默认 `out/`，见 `.gitignore`），**每步可单独复查**：

| 步骤 | 命令 | 产物 | 消费者 |
| --- | --- | --- | --- |
| 1 | `licaudit scan` | `inventory.json` | 人 / `assess` |
| 2 | `licaudit assess` | `profile.json`、`scenario.json`、`conflicts.json`（M4 起）、`actions.json`（M5 起） | 人 / `report` |
| 3 | `licaudit report` | `license-report.md`、`license-report.csv` | 人 / 审计留档 |

顶层统一带 `format` + `format_version`（自描述产物；装载器白名单分派，未知格式 exit 2）。JSON 序列化单点：

```python
json.dumps(obj, ensure_ascii=False, indent=2, sort_keys=False)  # 字段序由契约常量决定
# + LF + 结尾换行；写临时文件后 rename（原子写）；无时钟、无随机
```

### 3.1 对外字段契约（骨架阶段已落代码常量）

`src/licaudit/contract.py` 是唯一字段序来源；`SKILL.md` 契约块与它双向一致；测试做**集合相等 + 顺序相等 + 实际序列化命中字段序**三方断言。

- `INVENTORY_RECORD_FIELDS`：`package version raw_license spdx_id confidence evidence`
- `PROFILE_FIELDS`：`spdx_id tier obligations is_osi_approved is_fsf_libre patent_clause trademark_clause evidence`
- `SCENARIO_FIELDS`：`package scenario link_mode triggers verdict evidence`
- `CONFLICT_FIELDS`：`pair_id left right basis resolution evidence`
- `ACTION_FIELDS`：`package version spdx_id level reasons evidence`
- `REPORT_SECTIONS`：`概述 口径声明 证据锚点 逐包明细 风险分级 处置建议 待人工确认项 免责声明`

字段只在 `contract.py` 定义一次；其他模块 import 常量，不复制字面量。

## 四、退出码契约（锁进代码与测试）

| 码 | 常量 | 语义 |
| --- | --- | --- |
| `0` | `EXIT_OK` | 分析完成且无阻断项 |
| `1` | `EXIT_FINDINGS` | 分析完成，检出阻断/隔离级项，或 selftest 未通过 |
| `2` | `EXIT_USAGE` | 用法错误、输入不可用、未知许可证 ID |
| `3` | `EXIT_RULESET` | 规则包缺失 / 校验失败 / 版本不可识别 |

纪律：

- **不得**把「规则包缺失」退化成 exit 0 或「零依赖、无风险」。
- 领域异常继承 `ValueError`，由 CLI 显式捕获并映射；不允许裸 traceback 逃逸。
- 骨架阶段 `scan` / `assess` / `report` 因 `references/ruleset/manifest.json` 尚不存在而**真实地**返回 exit 3；这是 M1 的入口门，不是伪装。
- M2 起 `assess --profile-only` 已实现：仍未实现的子能力**先过规则包硬门**，再明确报「未实现」→ exit 2，不写占位产物。
  （**M5 起 `scan` / `assess` / `report` 三条通路全部实现**；`bench --only m6` 是唯一仍显式报「未实现」的入口，因为 M6 只有发布动作、没有判定套件。）
- 退出码语义表在 `SKILL.md`、`contract.py`、`tests/` 三处同步；改一处必须三处同改。

## 五、技术选型与弃选

| 决策 | 选中 | 弃选 | 理由 |
| --- | --- | --- | --- |
| 语言 | Python 3.8+ 纯标准库 | Node / Go / Rust | Skill 场景零安装成本；JSON/TOML 解析在 3.8 需自带，但只支持最小子集即可 |
| 打包 | setuptools + src 布局 | poetry / hatch | 零额外工具链；editable 安装即可用 |
| 配置 | `--rules-dir` / 环境变量 | 用户级配置文件 / 联网配置 | 纯本地、可复现、无隐式状态 |
| 规则格式 | JSON（人工可审） | YAML / SQLite | 标准库可读；YAML 需第三方依赖 |
| 报告 | 自写 MD/CSV | openpyxl / jinja2 | 字节确定、零依赖；CSV 用 `csv` 模块 + 固定 `lineterminator="\n"` |
| LLM | 不使用 | 解析兜底 / 复核 | 判定必须确定；见 D11 |
| 测试 | pytest（dev extra） | unittest | 项目惯例；CI 与本地一致 |

### 5.1 TOML 解析边界

`pyproject.toml`（PEP 621 与 Poetry）在 Python 3.8 无 `tomllib`。M1 方案：**自写受限 TOML 子集解析器**，只支持本项目需要的形态（表头、字符串、数组、内联表、布尔），遇到不支持语法 → 该依赖落 `truncated_fallback` + `待人工确认`，**不静默跳过**。若 M1 实测形态复杂度超出，再评估引入 `tomli`（仅 `dev` 或运行时依赖），届时登记决策。

## 七、失败路径与错误分类

| 场景 | 异常 | 退出码 | 是否留产物 |
| --- | --- | --- | --- |
| 未知子命令 / 缺必填参数 | argparse `SystemExit(2)` | 2 | 否 |
| 输入文件不存在 / 非 UTF-8 / 空文件 | `UsageError` | 2 | 否 |
| 清单格式可读但字段缺失 | 不抛错 | 0/1 | 是，落 `truncated_fallback` + 待确认 |
| 规则包目录 / manifest 缺失 | `RulesetError` | 3 | 否（不落空报告） |
| 规则包 schema/版本校验失败 | `RulesetError` | 3 | 否 |
| 检出阻断/隔离级 | 正常返回 | 1 | 是 |
| 内部未预期异常 | 不捕获为业务码 | 1（traceback 到 stderr） | 否 |

「没判定」与「判定为有问题」必须可区分：批量解析单件失败进 `待人工确认`，不改变整批退出码语义；退出码由「是否存在阻断级结论」决定。

## 八、CI 与工程门禁

`.github/workflows/ci.yml`：

- 矩阵：`windows-latest` / `ubuntu-latest` × Python `3.8` / `3.12`。
- `env: PYTHONUTF8: "1"`（CI 的 pytest 不是我们敲的命令，编码不能依赖 `-X utf8`）。
- 步骤：`pip install -e ".[dev]"` → `pytest -q` → **裸命令冒烟** `licaudit --version`、`licaudit selftest --core` → `python -m licaudit --version` → launcher 冒烟。
- 每一步显式断言退出码；`selftest --core` 必须 0，`scan`（无规则包）必须 3 的检查放测试里，不在 CI 用 `set -e` 猜。
- 首推前本地等价校验：双解释器全量 pytest + 两条安装通路冒烟。**未推送不写「CI 绿」**。

## 九、脱敏与品牌

- 仓库内只出现相对路径；用户侧启动命令才用绝对路径。
- 不提交 `out/`、`.venv`、缓存、报告运行产物。
- 示例与测试数据全部合成；真实包名只用于坑位回归（pandas / psycopg2 / PyMySQL / PyQt5），不进示例报告。
- 仓库名、Skill 名、文档不引用其他项目名称或模板。
