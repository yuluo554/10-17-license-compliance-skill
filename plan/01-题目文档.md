## 一、介绍

### 1.1 痛点：真实用户问的是"我这样用到底行不行"

开发者和团队真正卡住的不是"这个包是什么许可证"，而是"**我这个用法**会不会被传染、要不要开源、能不能卖"。公开社区里反复出现的是同一类问题（均为论坛原帖，链接可直查）：

## 二、任务要求（首期 5 个模块）

> 首期范围严格限定为 M1–M5。扩展项列在 §2.7，不算交付物。
> 每个模块的"输入 / 输出 / 确定性纪律"即验收口径，缺一不算完成。

### 模块 M1：清单解析与 SPDX 归一化

- **输入**：用户项目清单文件（一个或多个）：`package.json`、`package-lock.json`（v2 / v3）、`requirements.txt`、`pyproject.toml`（PEP 621 与 Poetry）、`go.mod`、`pom.xml`。
- **输出**：归一化记录 `(package, version, raw_license, spdx_id, confidence, evidence)`，逐条带**声明位置**（文件名 + 字段 / 行号）；整体落为 `inventory.json`。
- **可信度四级链**（严格按优先级，命中即停，不跨级合并）：
  1. `license_expression`：清单中的结构化表达式字段（如 package.json 的 `license` 对象 / `licenses` 数组、pyproject 的 license 表达式、pom 的 `<licenses>`）；
  2. `trove classifier`：`License :: OSI Approved :: ...` 一类分类器，经 curated 映射表转 SPDX；
  3. `license 首行`：仅取 `raw_license` 的**第一行**做锚定匹配；
  4. **截断兜底**：以上均不可用时，只保存截断后的原文证据，`spdx_id = null`，标"待人工确认"。
- **禁用全文关键词匹配（硬纪律）**：不得在许可证全文里搜索 "MIT"、"Apache" 等关键词来猜 ID。`pandas` 的 license 字段是经典陷阱——其全文极长（实测约 61K 字符），全文关键词匹配会误命中。第 3 级只允许首行 + 锚定模式。
- **表达式解析**：解析 SPDX 的 `AND` / `OR` / `WITH`；`WITH` 后的例外 ID 必须能在 SPDX exceptions 清单中命中（如 `GPL-CC-1.0`、`WxWindows-exception-3.1`），未命中标 `unknown-exception` 待人工确认。
- **版本语义保留**：**不得**把 `GPL-2.0-only` 归一化成 `GPL-2.0`，`-only` / `-or-later` 必须原样保留——它直接决定后续能否升级到 GPL-3.0；许可证版本无法确定时（只写 "GPL"、"Apache"），归一化为对应族系的 `<族>-unknown` 并标"待人工确认"，**不得默认取最新版**；包版本无法确定时记为 `*` 并标"待人工确认"。
- **确定性纪律**：解析器是纯函数，同输入同输出、无网络；每一条 `spdx_id` 必须挂规则包版本与 `detailsUrl` 证据；未挂原文核对不得落库；模型不得对清单内容做自由推断。

### 模块 M2：许可证画像与义务矩阵

- **输入**：`inventory.json` + SPDX `licenses.json` / `exceptions.json` 快照 + curated 义务矩阵规则包。
- **输出**：`profile.json`——每个 SPDX ID 映射到：
  - **传染强度五档**：宽松 / 弱传染（LGPL、MPL、EPL）/ 强传染（GPL）/ 网络传染（AGPL、SSPL）/ 源可用（BUSL、Elastic）；
  - **义务项集合**（枚举）：保留版权声明、附许可证全文、标注修改、提供对应源码、网络交互提供源码、专利授权、商标限制、同许可发布等；
  - **OSI 状态**（`isOsiApproved`）与 **FSF Libre 状态**（`isFsfLibre`，仅作辅助信息，不单独构成判定）；
  - **专利条款**、**商标条款**（有/无 + 条款锚点）。
- **规则来源纪律**：OSI / FSF 状态直接取 SPDX 字段；五档、义务项、专利/商标条款来自 curated 规则包，每条必须挂 `licenseId` + 条款出处（许可证文本中的节号或段落锚点）+ 核对日期。**未挂原文核对不得生效**。
- **确定性纪律**：五档定义与义务项枚举**只在规则包一处定义**，题面与报告只引用不复制；模型不得新增义务项、不得改档位。

### 模块 M3：使用场景判定

- **输入**：`inventory.json` + `profile.json` + 用户在交互式确认中给出的**交付形态**与**链接方式**。
- **场景枚举（八种）**：内部使用、分发二进制、分发源码、SaaS、静态链接、动态链接、独立进程、容器镜像。
- **必须纠正的常见误解**：**"商用即触发"是错的**。商业使用本身不是 GPL / AGPL 的触发要件，触发点是：
  1. **分发**（GPL 系）：把软件或其衍生作品交付给第三方；
  2. **网络交互**（AGPL §13）：即使不分发，只要用户通过网络与修改后的程序交互，就须向该用户提供对应源码。
  AGPL §13 是**独立触发点**，不能因为"没有分发"就判定不触发。
- **输出**：`scenario.json`——每个依赖的触发条件集合与判定结果（触发 / 不触发 / 待人工确认），并记录用户原始回答。
- **确定性纪律**：场景 × 链接方式 → 义务触发表写死在规则包中；交互式确认必须落盘用户原始回答；未回答或回答矛盾时输出"待人工确认"，**不得默认按最宽松场景处理**；模型只负责提问与转述，不负责判定。

### 模块 M4：冲突与兼容性分析

- **输入**：`inventory.json` + `profile.json` + `scenario.json` + **项目自身 outbound 许可证**（用户提供）。
- **输出**：`conflicts.json`——依赖之间的冲突、依赖与项目 outbound 许可的冲突、`AND` / `OR` 组合的求值结果，以及每条冲突的依据。
- **规则**：
  - 已知不兼容对必须可复现，例如 **`GPL-2.0-only` × `Apache-2.0` 不兼容**（Apache-2.0 的附加专利/赔偿条款构成 GPLv2 不允许的额外限制）；
  - **`OR` 取最宽松、`AND` 取最严格**；
  - 项目自身许可证未知时，输出"**待定**"，**不猜**、不按最宽松默认；
  - 传染范围按 M3 的链接/分发边界向上聚合；AGPL 聚合到网络服务边界。
- **确定性纪律**：冲突对来自 curated `conflict-pairs.json`，每条含 pair_id、依据条款、来源与核对日期；OSADL 兼容矩阵仅作**交叉验证**（官方端点当前不可用，见 §五），不作为唯一来源；模型不得判定兼容性、不得生成冲突对。

### 模块 M5：处置建议与清单输出

- **输入**：M1–M4 的全部结果。
- **输出**：中文《第三方开源清单》——Markdown + CSV 两种格式，固定章节：概述 / 口径声明 / 证据锚点 / 逐包明细 / 风险分级 / 处置建议 / 待人工确认项 / 免责声明。
- **四级处置**：可直接用 / 需补声明 / 需隔离（进程分离·容器边界）/ 需替换或取得商业授权。
- **每条处置必须挂五个证据锚点**：包名 + 版本 + 声明位置（文件 + 字段/行号）+ SPDX ID + 依据条款。缺任一锚点的条目只能进"待人工确认项"。
- **固定免责声明**（原样输出）："本清单由自动化工具生成，不构成法律意见（非法律意见）。涉及商业分发、诉讼或高价值交易时，请咨询执业律师。"
- **确定性纪律**：报告层的每个判定字段只能来自引擎输出；报告层**不得新增判定**（建议用 AST 门禁：报告模块不得 import 判定模块做二次推理、不得内联许可证 ID 判定表）；排序规则与字段顺序固定。

## 六、边界与非目标

- **不做完整源码许可头扫描与 SBOM 生成**：syft / scancode / ORT / reuse-tool 已覆盖，且需要重型依赖与构建环境。
- **不做 CVE / 供应链安全评分**：偏离许可证主线，且会与安全类 skill 撞车。
- **不做许可证文本自动分类模型**：一律用 SPDX 字段 + 规则包判定，确定性优先；禁止全文关键词匹配。
- **不做强制联网查询 npm / PyPI**：清单本地可解；SPDX 快照随包冻结，联网刷新仅作可选增强。
- **非法律意见**：输出仅供工程判断，固定免责声明原样保留；涉及诉讼、商业分发、高价值交易须咨询执业律师。
- **隐私红线**：纯本地处理，用户依赖清单与项目信息不上传；示例与测试数据全部使用合成清单。
- **品牌隔离**：本题只做**开源软件许可证合规**；文档、仓库名与 Skill 名不引用其他项目的名称、素材或文档模板，比较性表述仅作事实引用（如 §1.3 的工具对照）。
- **首期范围限定**：只承诺 M1–M5；§2.8 的扩展项不进交付物。
